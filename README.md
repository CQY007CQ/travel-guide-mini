# 旅行攻略生成器 · 微信小程序

> 括号内为「功能引入版本」，不是当前版本；当前版本见本文件头部，回归步数与单测条数以 `./allcheck.sh` 实跑为准。


一个**全程离线**的行程生成小程序：不调用任何大模型 API，所有行程由端上算法在本地算出。

输入「城市 + 天数 + 预算 + 出行偏好」，输出一份可执行的逐日攻略：每天的时段安排、景点间的
交通动线与步行量、能直接导航的真实坐标、预算拆解、打包清单、逐日天气（联网时才有，
断网自动降级）。城市数据与坐标随分包下发，**装机后完全不需要网络**。

- 版本：`1.20.2`
- AppID：`wxa365d49bc3366f95`（个人主体）
- 基础库：`3.8.12`
- 页面：主包 6 页（含 4 个 tabBar）+ 分包 12 页（功能 8 / 数据 3 / 内容 1）

## 一、它能做什么

| 能力 | 说明 |
|---|---|
| 行程生成 | 751 座城市任选；支持 1–10 天、3 档预算、4 种出行模式（亲子/情侣/独行/带老人）、3 种节奏（休闲/平衡/特种兵） |
| 多站串联 | 一次最多 4 站，自动排跨城顺序与每段天数 |
| 全省精华游 | 34 个省级行政区的省内跨城组合线路 |
| 真实坐标导航 | 绝大多数景点条目带真实 GCJ-02 坐标，点「导航」直接调起 `wx.openLocation`；没有精确坐标的自动退到城市锚点，不出现"假点" |
| 手动调整 | 上下移动、**按住手柄拖拽调序**、删除、换同类景点、加自定义景点、标记想玩、打卡打钩 |
| 行程体检 | 超出建议天数、务必预约未订、周一闭馆冲突、转场日无留白、预算偏紧 —— 一次列清，可一键减负 |
| 地图 / 美食 / 账本 | 按天切换的动线地图；404 城 6880 家真实名店，**点菜名可筛出做这道菜的店**；随手记账 + AA 分账 + CSV 导出 |
| 个性推荐 | 一句话说需求（「人少的古镇 三天」），端侧加权打分给候选城市并附理由；纯本地计算，不联网 |
| 旅途应急 | 受伤/突发不适时先给 120，再给「该挂什么科」，并按距离列就近医院（43 城 62 家，坐标经质量闸门校验） |
| 旅行档案 | 足迹（已去城市 / 打卡景点 / 成就徽章）、多行程存档、城市评分与避坑贴士、**本机数据洞察**（花费结构 / 月度趋势 / 省份分布 / 出行节奏，聚合自真实记账·存档·足迹） |
| 今日正当时灵感（v1.19.87） | 首页与「今天」页按当月时令推荐城市，点卡片即预填好目的地与天数，调完预算再一键生成 |
| 分享即种草（v1.19.88/89） | 行程页右上角转发生成一张黑金攻略卡，好友点开看到的正好是你这座城 |
| 城市深度玩法（v1.19.78 新增） | 10 座热门城市的本地节奏 / 避坑清单 / 取景机位 / 顺手加一日，人工整理离线内容 |
| 旅行人格 / 省章 / 想玩骰子（v1.9） | 看你属于哪种旅行人格、点亮去过的省份章、摇一摇随机抽一条想玩清单 |
| 工具箱 | 旅行百宝箱（行程体检 / 文案 / 灵感 / 百科等）、行程增强（问答式查漏 / 一键换景点 / 成就墙） |
| 可观测性（v1.19.106） | 本地错误日志：被兜住的异常留痕，真机/审核环境也能回溯；分包预下载加速首屏 |
| 离线容错 | 天气取不到会明说"天气暂不可用"并给重试；数据异常有全局兜底，不做沉默失败 |
| 出发提醒（v1.19.78 新增） | 一键写入手机日历（离线可用，到点响铃）；未来接上云开发后可升级为订阅消息推送 |

## 二、快速开始

```bash
git clone <你的仓库地址>
cd miniprogram-travel
```

1. 打开**微信开发者工具** → 导入项目 → 选择本目录
2. AppID：用正式 AppID `wxa365d49bc3366f95`，或改成你自己的测试号
3. 编译运行

**首次修改代码前，请先看这两件事**（都是踩过线上事故的坑，见 `docs/design/ARCHITECTURE.md` 第七节）：

- 改 `utils/data.js` 无效 —— 它是生成产物，真源在 `tools/_src-backup/data.js`
- 增量改数据只能走 `tools/_apply-safe.mjs`，**禁用 `merge-data-patch.mjs`**

## 四、数据管道

数据改动**只能**走这条链，顺序不能颠倒：

```bash
node tools/_apply-safe.mjs        # 1. 以当前 packed 为底，叠加 tools/v19N-*.js 增量补丁
node tools/pack-data.mjs          # 2. 重新打包、分块、写 subdata*/data/data-packed*.js
./allcheck.sh                     # 3. 全量回归
```

| 规则 | 为什么 |
|---|---|
| 补丁文件名必须匹配 `/^v19\d-.*\.js$/` | 管道按此识别增量，避免误把一次性脚本当数据补丁 |
| **禁用「整体替换」式合并**（原 `merge-data-patch.mjs` 已移出仓库） | 它做整体替换，曾把 `CITIES_ADD` 覆盖导致 experiences 塌回 8655 条 |
| 打包器内置"脏键清理" | 自动剔除 `SPOT_COORDS` / `CITY2PROV` 里的非直辖市省名键，否则跨省解析会串城 |
| `require.async()` 实参必须是静态字符串字面量 | 传变量会导致微信解析不到分包 → 数据永不加载 → **首页白屏**（线上事故根因） |
| 键别名压缩已停用 | 与 `_apply-safe` 的读写不同源，会互相污染导致键损坏 |
| 坐标与美食去重走 `tools/lib-near-dup.mjs` | 「同一景点」的判定只有一处真源，避免扫描器与写入端规则漂移（曾导致每日任务连续多天空转） |
| 美食增量批次 `v202-food-shops2.js` | 店名来自公开资料、坐标由 `geocode/geo` 取得并经质量闸门（地址含预期街道 / 非公交站 / 距城中心 ≤25km） |

## 七、合规

- **无任何第三方 Key 明文入库**：被停用的他人 KEY 在 `_amap-compliance.mjs` 里只存 `sha256` 摘要
- 运行时 App 端零高德依赖：天气走 open-meteo，地图走原生 `<map>`
- 深度玩法内容是**人工整理的离线文本，不是实时 AI 生成**，不适用生成合成内容的标识要求；涉票价班次的信息都标注"以官方当日公告为准"
- 广告、订阅消息均做成**开关式**：未配置即自动隐藏/全解锁，不会出现"点了没反应"的功能
