# 文档中心（docs/）

本目录集中存放项目的**非运行时文档**，均不参与微信小程序的编译与打包。

历史：项目根目录原本散落约 35 个 `.md` / `.html`（版本变更、审核描述、技术方案、架构、优化清单等），
于 2026-10-19 首次按性质分层归集；2026-11-17 二次整理把**根层残留的最后 15 个文件**全部归位，
现在 `docs/` 根层只剩本索引，**新增文档一律直接落到下面的子目录**（有门禁 `check-structure` 守着）。

## 目录结构

- **`changelog/`** —— 版本演进记录：逐版本变更清单、审核描述、隐患排查、路线图、迭代汇总。
- **`design/`** —— 架构、技术方案、方案调研与设计决策。
  - `ARCHITECTURE.md`：项目架构总览（分层、数据管线、模块职责）
  - `v1.20-*` / `v1.21-*` / `v1.22-*` / `v1.23-*`：后续版本技术方案（云后端与 AI 行程、旅行排行榜、
    deep 扩容候选、高德抓取与并发写入排查、高德封禁处置与合规加固、外借 KEY 停用与自主申请、善后沟通）
  - `合规-API-key归一方案.md`、`cloud-sync-guide.md`：合规与云同步实施说明
  - `计划-冷启动数据分块.md`、`每日自主扩增与优化引擎.md`：已设计待实施 / 长期机制类方案
  - `500项优化清单.md`、`B2-包体安全线核查报告.md`、`真实体验10项改进-v1.19.9.md`：清单与分析
  - `朋友圈分享卡.html`：分享卡片素材 / 模板
- **`audit/`** —— 代码审计与质量报告（一次性的深度体检结论，含问题清单与整改证据）。
- **`qa/`** —— 产品测控报告：按「六级缺陷清单 + 已修/未修 + 未测范围」组织，与 `audit/` 的区别是
  `audit/` 看**代码实现**、`qa/` 看**产品行为**（含真实执行轨迹与踩坑记录）。
- **`assessment/`** —— 考核 / 评审用材料。
  - `功能清单.md`：功能字典（按模块梳理已实现功能，文末单列「考后规划中」）
  - `演示讲稿.md`：演示讲稿（疑问式开场与边看边讲双版本合一）
  - `demo-runbook-2026-11-09.md`：演示前自检与跑分手册
  - `功能对照-小程序版 / 网页版-2026-11-10.md`：两端能力逐条对照
- **`prompt-engineering/`** —— 提示词工程：目标提示词、候选与评测方法、实测报告。
  - `prompt-engineering-deliverable.md`：通用提示词交付（终极提示词母本）
  - `prompt-engineering-travel-assistant.md`：旅行助手领域的 14 个候选 + 终极提示词
  - `prompt-travel-guide.md`：终极提示词在「旅行攻略生成」场景的实例化
  - `提示词工程报告.md`、`PROMPT_ENGINEERING_DELIVERY.md`：方法论与交付说明
  - `runs/`：真机/真实调用的逐轮输出留档（评测证据链）
- **`spoke-prompts/`** —— 分支机（团队分布式开发）用的分区域提示词模板。

## 约定

- 项目根 `README.md` 是工程入口说明，本目录是其配套的文档归档。
- 这些文档**不会被微信开发者工具编译进小程序包**（`project.config.json` 的 `packOptions.ignore` 已排除 `docs`）。
- **根层只放本索引**：`tools/check/check-structure.mjs` 会断言 `docs/` 根层除 `README.md` 外没有散落文件，
  避免再回到「35 个 md 堆在根目录」的状态。
- 优化清单类由生成脚本产出，输出路径已对齐 `docs/design/`，重跑脚本无需手动搬运。
