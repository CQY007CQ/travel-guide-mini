## 新增工具：`tools/fetch-amap-spots.mjs`（双通道）

- `--mode around`（默认）：按城市锚点做 `place/around` 周边搜索，取 `110202|110203`（国家级/省级景点）与 `110000`（风景名胜，评分 ≥4.5 门槛），**带评分/开放时间**，质量最高。
- `--mode inputtips`：搜索配额用尽时的替代通道，12 个景区关键词 + 类型码 `11xxxx` 过滤，**带真实地址与坐标**（无评分）。
- 抓取过滤：城市归属校验（cityname/adname/district）+ **距城市锚点 ≤120km 硬校验** + 噪声名/裸通用名/子条目过滤 + 核心名近似去重（折叠「龙子湖公园/龙子湖风景区」这类同地异名）。
- 参数：`--only 城,城` / `--limit N` / `--fresh` / `--skip-uncached`（只重筛缓存、不耗配额）/ `--base <快照>`（按原始库生成完整补丁）。
- 缓存断点续传 `tools/amap-spots-cache.json`；补丁与已有补丁**并集合并**（多轮/换通道不互相覆盖）。
- 产出补丁 `tools/data/v199-amap-spots.js`，三键：
  - `LM_ADD` → 进「本市真实景点补充池」（行程空槽自动补入，**无需编造介绍**）
  - `COORDS_ADD` → 真实 GCJ-02 坐标 → 就近排序 + `wx.openLocation` 一键导航
  - `SPOT_INFO` → 真实地址 / 开放时间 / 评分 / 人均（缺项不填，不虚构）

## 重要修复：苏州 id 改名遗留的附属数据错挂（既有 bug）

- **现象**：查「宿州」生成 4 天行程，输出的是**苏州的景点**（留园、沧浪亭、可园、狮子林、网师园、盘门景区）与苏州酒店（平江路·观前街）。
- **根因**：v1.15 把苏州 id 由 `suzhou` 改为 `suzhou_jiangsu` 时，只改了 `CITIES`，**未同步迁移按 id 索引的 `HOTELS` / `EXTRA_SPOTS`**。这两个键仍留在 `suzhou` 下（内容全是苏州的），而 `suzhou` 这个 id 现在归属「宿州」→ 宿州错拿苏州数据；同时苏州自己反而没有酒店与候选景点。
- **修复**：`merge-data-patch.mjs` 新增 `ID_REKEY` 补丁键（迁移按 id 索引结构的键，幂等重放安全）；`tools/v199-fix-suzhou-id.js` 把 `suzhou → suzhou_jiangsu` 迁回。
- **验证**：`HOTELS.suzhou`/`EXTRA_SPOTS.suzhou` 已清除并迁至 `suzhou_jiangsu`；宿州行程现全部为本地真实景点（宿州博物馆、皇藏峪、萧县天门寺、灵璧奇石园、泗县石龙湖、砀山酥梨园、砀山黄河故道），残留苏州景点 **0**。
- 同时扫描全库：`CITIES` 无重复 id，无其它孤儿 id 键。

## 测试修复：`check-boundary.mjs` D1b 断言缺陷

- **现象**：新增安阳「人民公园」后 D1b 失败。
- **根因**：旧断言要求「同一省内**每一座**拥有该名的城市，省域查询都要等于它自己的坐标」。当河南省的郑州与安阳都有「人民公园」时，一个查询不可能同时等于两个值 —— 断言自相矛盾（旧写法在「省内 ≥2 城同名」时必然误报）。
- **修复**：改为「省域查询结果必须落在**本省拥有该名的城市之一**的坐标上」＝真正要守住的「不串到省外」。另：不额外断言各省坐标互不相同（壶口瀑布属晋陕界、泸沽湖属川滇界，跨省共用同一坐标是正确的）。
- 结果：203 通过 / 0 失败。

# 追加（同日）：Key 池化改造 + 工具链修复

## 一、查清「配额用尽」的真正原因（官方口径）

高德开放平台 FAQ 的 Web 服务配额表：

| 能力类别 | 个人认证开发者 | 企业认证开发者 |
|---|---|---|
| 地理编码 / 逆地理编码 / 坐标转换 / 行政区 / IP 定位 / 静态地图 | 5000 次/日 | 30 万~300 万次/日 |
| 路径规划类（驾车/公交/步行/骑行/距离测量） | 5000 次/日 | 30 万次/日 |
| **搜索类（周边搜索 / 关键字搜索 / 输入提示 / ID 查询 / 多边形搜索）** | **100 次/日** | **1000 次/日** |

**结论**：账号没问题、Key 没问题，卡在「搜索类只有 100 次/日」。按 `inputtips`（12 次/城）
计约 8 城/日，按 `around`（2–6 次/城）约 15–30 城/日。**再申请单个 Key 也解决不了，
正确策略是「多把 Key 轮换 + 每日分批推进」**。

## 二、`tools/fetch-amap-spots.mjs` 升级

- **Key 池**：新增 `tools/geocode.keys`（一行一把，`#` 注释；与旧 `tools/geocode.key` 兼容并存；
  另支持 `MAP_KEYS` 环境变量）。文件已 `chmod 600`，并写入 `.gitignore` 防误入库。
- **自动轮换**：新增统一请求层 `apiGet()`，命中
  `OVER_LIMIT / INVALID_USER_KEY / USER_KEY_RECYCLED / INVALID_USER_SCODE / USERKEY_PLAT_NOMATCH / INVALID_USER_IP / SERVICE_NOT_EXIST`
  时自动切到下一把 Key **并重试同一请求**，全过程打日志。
- **全废即停**：所有 Key 均不可用时立即结束本轮，不再把剩余 200+ 城空跑一遍。
- **`--check`**：体检「每把 Key × 5 个接口」，拿到新 Key 先验一把再开跑。
- **`--budget N`**：本轮接口调用数上限，到点主动收手，把配额留到下一次（应对 100 次/日的个人配额）。
- **实测**：① 假 Key + 真 Key 混装 → 正确打印 `[key 轮换]` 并接续到真 Key；② 预算闸门 3 次后第 4 个探针被拦。

## 三、修复：`allcheck.sh` 因托管 node 升级而全线崩溃（重要）

- **现象**：回归链 **16 步全 ✗**，报 `/…/node/versions/22.22.2-2/bin/node: No such file or directory`。
- **根因**：`allcheck.sh` 里**写死了托管 node 的绝对路径**，而托管运行时已从 `22.22.2-2` 升到 `22.22.2-3`。
  **与数据无关**——16 个红叉极易被误判成「数据坏了」而去做无用的数据回滚。
- **修复**：三级解析 → `NODE_BIN` 环境变量 → `command -v node` → 托管版本目录下 `sort -V | tail -1`；
  全部失败时给出明确提示并退出。
- **修复后**：`./allcheck.sh` **16/16 全绿**。

## 四、定时任务调整

- 原「次日 08:00 一次性续抓」→ 改为**每日 08:00 循环执行**（高德搜索配额 100 次/日，必须多日分批）。
- 任务 prompt 已写明：先 `--check` 探活 → `--mode around --budget 90` → 合并/打包/回归三步 →
  汇报剩余城市数与预计还需天数；剩余为 0 时提示可删除该任务。
