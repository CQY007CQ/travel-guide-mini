## 一、真实用户测试结论（已跑，非空谈）

用 `tools/realuser-test.mjs` 模拟 10 类用户场景（热门/长尾/小城/极限天数/全省/多站/特种兵），结论：

- ✅ **结构健康**：无空泛日、无时段倒挂（框架项边界除外）、无崩溃、无重复真实景点。
- ✅ **新数据已生效**：芜湖 3 天出 6 个真实景点、宿州 2 天出 4 个，全部带精确坐标可直接导航 —— 长尾城市"有攻略可玩"的问题已实质性解决。
- ⚠️ **唯一观感问题**：北京 4 天里"休整 · 周边走走"这类 relax 填充项出现 3 次，会让行程显得"水"。属文案轮替问题，非 bug。

## 三、推荐优化项（按优先级）

### P0 · 高感知、低成本
1. **首页首屏信息过载**：品牌头 + 快捷入口 + 倒计时 + 预约横幅 + 主卡 + 首访引导 + 想玩池 + 快捷回填 + 恢复提示 + 生成按钮，首屏最多可能叠 9 个区块。建议把"首访引导"改为**一次性轻提示**（看过即不再常驻卡），"想玩池/快捷回填"维持按需出现，降低首屏压迫感。
2. **relax 填充项去重轮替**：同一文案（"休整·周边走走"）在松行程里重复出现。建议准备 3-4 条同义措辞轮换（如"老街慢逛 / 咖啡馆发呆 / 近郊步道"），且单行程最多插 1 次。
3. **行程页默认折叠**：攻略速览 / 城市速览 / 天气 / 行程体检 / 想玩清单 目前默认全展开，长行程滚动很长。建议默认只展开"攻略速览 + 天气"，其余收起。

### P1 · 中感知、中成本
4. **地图页动线可视化**：目前地图只展示 pin，路线建议是纯文字。建议在 `map` 页加"按天切换 + 当天 polyline 串联"（approx 兜底已可用），用户在地图上直接看到今天怎么走。
5. **LM_ADD 地标转正进 experiences**：239 城已铺真实地标池，但只在生成时空槽补入，"想玩池"里这些新城仍可选景点少。建议把各城高频地标**转正**进 `experiences`（至少补到 8-10 个/城），让"想玩"真正可选、行程更饱满。当前仍有 226 城 experiences < 14。
6. **指南页数字运行时化**：指南里"372 城"等数字仍手写，本次恰好准确，但每次发版易过期（历史已踩过）。建议关键数字改为运行时读取（城市数、工具数），一劳永逸。

### P2 · 长期、需规划
7. **精确坐标继续补**：坐标 7041 条，但部分仍是 `approx="city"` 城锚兜底，点"导航"会落到市中心而非景点。高德双 Key 配额已就位，可继续对 Top 旅游城市补精确坐标。
8. **主包体积预警**：当前 1.77MB，余量仅 236KB。继续扩数据会触 2MB 红线。建议把 `SPOT_INFO` 详情文本改为**按需懒加载**（进详情才取），或评估分包。
9. **"更多"工具闭环**：美食名店 / 本地速查等结果是卡片，用户希望"加入某一天行程"或"收藏"。建议工具结果增加"加入行程 / 收藏"出口，形成闭环。

## 四、本轮未做（说明）

- 真机/DevTools 可视化回归：沙盒无法启动微信开发者工具 GUI，UI 减法以代码审查 + 变量修色为主，未做像素级目测。建议你本地 `cli open` 后扫一眼首页与暗色模式。
- 全省/多站极限天数的"时段倒挂"警告：经核查为框架项（返程/抵达）的 period 映射边界，不影响用户阅读，暂未改。
