## 二、阶段一 · 冷启动白屏根除（10.25，v1.19.96–101）

一次"开机白屏"用户报障，查出的是**三个叠加的独立缺陷**，逐个挖到真根因：

| 版本 | 定位 | 修复 |
|---|---|---|
| 1.19.97 | `splash.json` 原生底色仍是深色 `#0a0f1c`，冷启动首帧被微信画成黑屏 | 底色改 `#eaeff7` 随主题；`onLaunch` 存储恢复整体包 try/catch |
| 1.19.98 | splash 顶层 `getApp()` + `require` 抛错 → `Page()` 从未执行 → 页面未注册 | 删未用 `getApp()`、`require` 包兜底，**保证 `Page()` 必然注册** |
| 1.19.99 | **真根因**：`data.js` 顶层 `process.env.DATA_CHUNKS` → 微信无 `process` → `ReferenceError` → 数据模块崩 → 所有页面全白 | 加 `typeof process !== "undefined"` 守卫 |
| 1.19.100 | 首页按钮全部失效：`getApp()` 在模块顶层取值，`lazyCodeLoading` 下为 `undefined`，初始化中断 | 改为惰性取值 |
| 1.19.101 | 地图页 `MARKER_CAP` 未声明 → 下一页/图层按钮失灵 | 补声明 + 新增全工程 handler 冒烟测试 |

**结论（已固化为经验）**：白屏 ≠ 底色问题。判据是"页面是否被注册"——顶层任一异常都会让 `Page()` 不执行，因此**页面入口的顶层代码必须无裸副作用**。这个教训后续演化为 `SafePage` 错误边界。

## 五、阶段四 · 合规内容大扩容（10.29，v1.19.112–137）

单日 26 个版本，是全程密度最高的一天。核心原则：**合规不可协商，宁可改设计也不改红线**。

### 5.1 旅途应急（v1.19.116 起，全程 13 城 16 家 → 451 城 1728 家）
用户原始需求是"推荐擅长某科的医院"。**没有照做**——导向无急诊能力的医院会延误救治、个人主体无医疗资质、"某院擅长骨科"无权威结构化来源。改为**分层信息设计**：首屏 120 主行动 → 该挂什么科（17 条分诊规则）→ 就近医院中性列表（距离/等级/导航，纯几何排序）→ 免责声明。全程 8 个禁词红线断言守着，不含任何"擅长/首选/推荐去"。

数据来源只用 `geocode/geo`（地址→坐标，合规），配双重闸门：地址文本须含"医院" + 距城中心 ≤25km。**按医院名 geocode 极易错配到公交站/远郊院区**，故逐条校验，21 家候选只入 16 家。

### 5.2 美食内容

### 5.3 全站减负（用户问卷反馈"字太多"）

## 十、踩坑沉淀为护栏（精选）

1. **白屏判据**：查"页面是否被注册"，不是查底色；页面顶层禁裸副作用。
2. **`process` 缺失**：任何 `.js` 顶层用 Node 全局都会在微信端崩，`typeof` 守卫是唯一解。
3. **BSD grep 的 `\|` 静默返回空** → 一律用 ripgrep，多模式搜索拆开写。
4. **批量合并数据前必须归一字段名**（`km` vs `kmc` 让 16 家医院距离变 undefined，被回归抓住）。
5. **改坐标前先 `git checkout` 还原原始坐标再重打包**，否则会把误编码固化。
6. **压缩产物不手改**：一律 `_src-backup` 源码 + `build-min` 再生，`verify-release` 校验 src==out。
7. **残包门禁**：subdata ≈1.74MB，跌破即说明数据分包被静默剥离。
8. **`fetch({timeout})` 无效**，用 `AbortSignal.timeout()`；`page` 上没有 `evaluate()`，真机截图 tabBar 页必须 `switchTab`。
