> 用户要求（2026-09-09/10）：不含港澳台覆盖 4 直辖市 + 293 地级市（含自治州/地区/盟共 333 地级行政区）；每城 ≥14 景点；每城 ≥5 家真实美食店；每个景点带名称/价格/开放时间/最佳游玩时间/交通指南/具体非泛泛介绍；全景点一键导航；景点标签多维检索；攻略生成可偏向历史/自然/默认；全文不虚构不雷同；整体优化；bug 修复；抽检流畅；UI 减法；最终上传。

## 已完成（本里程碑）
- **行政区覆盖审计**：`tools/dev/cities-census.mjs` 内嵌 337 地级行政区标准清单（4 直辖市 + 293 地级市 + 自治州/地区/盟），CITIES 365 全量覆盖，**主缺口 0**。工具同时报告每城景点 <14 / 美食店 <5。
- **景点标签**：`spotTagOf(name)` 规则化分类（历史古迹/自然风光/博物馆/宗教/古镇/亲子/乐园/美食/海滨/徒步/其他），SPOT_DETAIL 可显式 tags 覆盖。
- **多维检索**：`searchSpots({city, tag, kw})`，按城市 + 标签 + 关键词过滤，返回带标签景点。
- **攻略风格偏好**：`buildPlan`/`buildMultiPlan`/`buildProvPlan` 支持 `bias:"history"|"nature"|""`；单城在就近评分叠加偏好，全省游在每城内部排序偏好景点。
- **一键导航**：沿用 v1.14 approx 三态，全景点可达率 100%（精确 62.5% + 城锚兜底 100%，null 0）。
- **回归**：allcheck 12/12、check-new 358/358、fuzz 24120 零崩溃、全省生成 306/306、坐标 null=0。
- 数据规模：CITIES 365 / experiences 2856 / SPOT_COORDS 2397 / FOOD_SPOTS 城市 40。

## 剩余缺口（审计口径）
- **每城 ≥14 景点**：当前 365 城景点总数 2856，需补到 ≥5110（365×14），缺口约 **2250+ 条**。
- **详情六字段**：`SPOT_DETAIL` 已设计但数据尚未批量填充（价格/开放时间/最佳时间/交通/具体介绍/标签）。
- **每城 ≥5 家真实美食店**：FOOD_SPOTS 仅覆盖 40 城，需补到 365 城 × ≥5 家；**必须用真实 POI 数据源核验（腾讯地图/高德），禁止编造店名地址**。
- **多维检索 UI**：底层函数已就绪，页面入口未接（后续 milestone）。
- **UI 减法 / 性能抽检 / 最终上传**：待数据质量达标后执行。

## 执行批次（数据优先，按省推进）
1. **景点扩到 14/城**：每批 3~5 省，复用 CITIES_ADD/EXP_REPLACE/COORDS_ADD；新增景点必须带真实名称与具体 note，禁止“泛化”。
2. **详情六字段**：`SPOT_DETAIL[城市][景点] = {price, hours, best, howTo, desc, tags}`；旗舰先做，普通景点后补；只写能核实的信息，不确定字段写“以景区当日公告为准”而非编造数字。
3. **美食店 5/城**：接入真实 POI 数据源（需用户提供腾讯地图 Key 或授权联网核验），落 FOOD_SPOTS。
4. **检索 UI**：在 plan 页/地图页接 `searchSpots`，标签筛选 + 关键词 + 城市切换。
5. **风格偏好 UI**：出发页生成时加“历史古迹 / 自然风光 / 默认”分段选择，透传 bias。
6. **真实性抽检**：脚本抽查详情文本相似度（雷同率）+ 事实性人工抽检。
7. **UI 减法 / 性能**：砍低频入口、统一密度、抽检真机流畅。
8. **最终上传**：全部验收通过后 `cli preview` → `cli upload`。

## 铁律
- 不编造坐标、不编造店名/地址、不编造价格与开放时间；不确定的写“以景区/门店当日公告为准”。
- 每个景点介绍必须“指到具体地点/具体看点”，禁止“历史悠久、风景优美”这类模板句。
- 每批必须跑 `allcheck.sh` + fuzz + 全省生成回归 + a2 坐标扫描。
