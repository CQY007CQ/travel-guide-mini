# v1.23 外借 KEY 事故善后：损害评估、责任归属与对方沟通方案

> 日期：2026-09-14 ｜ 背景：本项目使用他人实名账号的高德 KEY 跑批量抓取，
> 高德依《服务协议》4.12.3 摘除该 KEY 的 `v3/place/text` 接口权限，处置落在**对方账号**上。

---

## 一、先定性：这件事到底有多严重

不要自己吓自己，用三条实测事实把严重程度框住：

| # | 事实 | 证据 |
|---|---|---|
| 1 | 处置是**接口级**，不是账号级 | 被封 KEY 调 `geocode/geo` 仍返回 `10000 OK` |
| 2 | 从未出现 `10026 INVALID_REQUEST` | 该码是唯一的账号级封禁码，出现即全账号 KEY 作废 |
| 3 | 被封 KEY 的多数接口仍然健康 | `geocode/geo`、`regeo`、`direction/driving`、`config/district` 全部 OK |

**结论：不是"把人账号搞废了"，而是"在对方账号上留了一条违规记录，摘掉了一个接口"。**

### 影响面取决于对方是否用 `place/text`

| 对方可能的使用场景 | 是否受影响 |
|---|---|
| 地图展示 / 定位 / 地理编码 | ❌ 不受影响 |
| 路线规划 `direction/*` | ❌ 不受影响 |
| 行政区划 `config/district` | ❌ 不受影响 |
| 周边搜索 `place/around` | ❌ 不受影响（仅配额） |
| 输入提示 `assistant/inputtips` | ❌ 不受影响 |
| **关键字搜索 `place/text`** | ✅ **唯一受影响** |

`place/text` 是关键字搜 POI，**多数个人开发者根本不用**（要坐标用 geocode，要周边用 around）。
所以对对方的**实际业务影响很可能接近于 0**；真正的残留影响是**账号上多了条违规记录**——
这条会影响他后续申请更高配额、企业认证、或申请商务许可时的审核。

## 二、责任怎么算（按协议原文口径）

| 条款 | 内容 | 指向 |
|---|---|---|
| 3.6 | 未经同意将账号下服务交第三方实际使用，**双方承担连带责任** | 双方 |
| 4.5 | KEY 不得转让、出租、**出借**、披露、泄露 | 对方（出借动作本身违约） |
| 3.5 / 4.12.3 | 禁止抓取、**存储、缓存**服务数据（**本次封禁依据**） | 本机（实际抓取动作） |

拆开看会清楚很多：

- **违规动作发生在本机**：批量抓取 + 落盘，是 `tools/` 里的脚本跑的 → 主责在**实际使用人（你）**。
- **对方的责任视"是否知情同意"而定**：主动借出 → 他也违了 4.5；不知情被拿走 → 他是受害方。
- **协议上"出借"和"抓取"是两条独立的违规**，不是一回事。

**但这不是需要争的事。** 争责任只会让关系更糟，而且你确实是触发方。
**正确姿势：把处置做到位，让对方零成本。**

## 三、补救的正路：那封函件里留了口子

原函件里有一句被 OCR 弄花的原文，语义还原是：

> 如以上违规行为系因第三方违法违规使用引起的，请通过工单联系我们。

**这句话就是为这种情况准备的**，而且——**只有账号主体本人能提工单，你提不了。**

### ⚠️ 但提工单有反作用，必须由对方自己判断

- 提工单 = **书面承认"KEY 曾被第三方使用"** → 若被认定为"未经同意的泄露"，可能追加 4.5 的处置。
- 因此措辞必须落在「曾提供给朋友做**个人学习性质**的小项目，现已**回收并停用**」，
  **绝不能说成"KEY 被泄露/被盗用"**。

### 决策树（按风险从低到高）

| 对方情况 | 建议 | 理由 |
|---|---|---|
| 完全不用 `place/text` | **不提工单**，静默止损 | 已无持续损害，提工单反而把"外借"写进记录 |
| 要用 `place/text`，或在意账号记录 | **由他本人提**，措辞按模板 | 函件明确邀请了这条路，且只有他能提 |
| 账号下还有其他商业项目 | **尽快提**，并优先确认其他 KEY 状态 | 需要把"已整改"作为事实固定下来 |

## 六、要不要主动提赔偿

- **民事索赔在本案基本不成立**：无明显实际损失（接口级处置 + 该接口多半他用不上）。
- **风险不在钱，在两处**：① 他账号下别的项目可能被牵连；② 他后续申请配额/认证时的审核记录。
- **建议主动说明 + 提供协助，但不要主动提钱**。主动提钱会把关系定性成交易，
  反而强化"我造成了损失"的印象；而在他没提出损失前，正确的补偿方式是
  「把善后做完 + 随时配合」。
