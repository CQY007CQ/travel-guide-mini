# v1.20 深度玩法（deep）扩容候选清单

> 生成于 2026-10-15，数据源：`utils/travel.js`（v1.19.90）+ `subai/data/ai-deep.js`
> 统计口径：未来 365 天（完整 12 个月轮换周期）× 每日 3 张「今日正当时」卡的曝光频次

## 一、为什么要扩容

- 现有 deep 精编仅 **10 城**（北京、上海、西安、成都、重庆、杭州、南京、广州、厦门、青岛）
- 「今日正当时」灵感卡未来 30 天的 deep 命中率仅 **3%**（3/90）——种草→行程页的「深度玩法」惊喜卡 97% 不出现
- **反直觉发现**：已有 deep 的 10 大城年曝光只有 1-5 次（淹没在 92-337 城的大池轮换里），而年曝光 6-10 次的高频城市（临汾、昆明、腾冲、潮州…）反而零精编。**扩容优先级应由曝光频次决定，而非城市体量。**

## 三、内容模板（每城 schema，与现有 10 城同构）

```js
"城市名": {
  "teaser": [ /* 恰好 3 条，行程页直接展示的钩子 */ ],
  "blocks": [
    { "t": "本地人的节奏", "items": [ /* 3-4 条：真实作息、本地人怎么玩 */ ] },
    { "t": "避坑清单",    "items": [ /* 4-6 条：预约规则、坑人街区、替代方案 */ ] },
    { "t": "取景机位",    "items": [ /* 2-3 条：时间+点位+光线 */ ] },
    { "t": "顺手加一日",  "trips": [ /* 2-3 个周边城：name/meta(交通)/why */ ] }
  ]
}
```

**质量红线（沿用 ai-deep.js 头注释，勿删）**：
1. 人工整理、随版本静态下发的离线文本——**不是实时 AI 生成**，不适用生成合成标识要求
2. 票价/班次/开放时间/预约规则会变——**一律写「以官方最新公告为准」类兜底**，不写死价格
3. 风格对齐现有 10 城：口吻是「本地朋友给的实用建议」，不是导游词；每条要有具体时间/地点/替代方案

## 四、产能节奏建议

- **每周 2 城**（半天/城），P1 批次 20 城约 10 周完成
- 完成后灵感卡 deep 命中率：3% → 预估 25-30%（年曝光前 40 城覆盖大部分轮换日）
- 每批 5 城合一次版：`ai-deep.js` 手工追加 → `node --check` → allcheck → 上传（subai 分包富余极大，25.7KB/2MB）
- 内容生产流程：我按模板起草 → 你以本地人/去过的人视角审校事实 → 合入

## 五、附：真机走查清单（每次发版后 5 分钟）

1. **冷启动**：杀掉小程序重开 → splash 正常过渡（浅色底，无黑屏）
2. **今日正当时**：首页横滑卡 3 张 → 点一张 → 表单已填好该城 + 天数收敛
3. **生成**：默认参数点生成 → 行程页出现 → 深色模式切换往返一次
4. **行中卡片**：today 页（无行程 → 看灵感卡；有行程 → 各阶段卡片）
5. **分享**：行程页生成海报 → 保存；右上角转发 → 卡片图是黑金 5:4 图
6. **拖拽**：行程条目按手柄拖动排序一次
