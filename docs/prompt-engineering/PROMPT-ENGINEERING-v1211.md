## 二、候选池：16 条 × 8 维

8 个可调维度（每维 5 档）：推理深度 / 输出篇幅 / 格式严格度 / 情感倾向 / 术语密度 / 检索依赖 / 自检强度 / 风险姿态。

16 条候选由**条款库渲染**而成，除被调维度外其余条款逐字相同——这样分数差才能归因到设计，而不是笔误。
池子自洽性自检：向量合法 0 越界、id 唯一、无重复向量、**0 条硬冲突**（软冲突 2 条已登记）。

`detectConflicts()` 拦下的硬冲突（这些组合写进提示词会自相打架，直接不许进池）：
深推 × 极简篇幅、高术语 × 热忱口吻、进取 × 强制引用、五项自检 × 极简、字段级格式 × ≤300 字。

## 三、量化评分模型：4 主维 × 4 子指标

| 主维 | 子指标 |
| --- | --- |
| A 准确性 | A1 零伪造护栏覆盖 / A2 检索落地度 / A3 数据可核验性 / A4 不确定性显式化 |
| C 可控性 | C1 格式确定性 / C2 篇幅可控 / C3 角色边界清晰 / C4 指令无矛盾 |
| M 完整性 | M1 八项纪律覆盖 / M2 分步链完整 / M3 自检节点 / M4 交付物定义 |
| R 鲁棒性 | R1 冲突消解 / R2 降级路径 / R3 长度适配 / R4 复跑稳定 |

分数**不是**按设计意图给，而是从「渲染出来的提示词文本」测量特征后落档（字数上限、字段数、禁令条数、来源要求、自检条目数、步骤数……）。每档锚点写在 `rank.mjs` 的注释里。

### 偏置控制（四项，全部有断言）

| 偏置 | 来源 | 做法 | 结果 |
| --- | --- | --- | --- |
| 评分项顺序偏置 | arXiv 2506.22316 | 6 组种子化乱序各算一次，断言排名完全不变 | 6/6 通过 |
| 分档编号偏置 | 同上 | 编号换成不透明 `B1..B16`，断言分数不变 | 通过 |
| 参考答案分数偏置 | 同上 | 三链权重彼此独立、无共享参考答案 | 最大余弦 0.8928（阈 0.9，**边界通过**） |
| 中心倾向偏差 | 剑桥 OpRaise | 每档写可观察证据锚点 + 要求首尾分差 ≥15 | 3/3 达标（25.28 / 32.29 / 25.55） |

## 四、三条独立链 + 多数投票

| 链 | 主张 | 第 1 名 |
| --- | --- | --- |
| S 结构派 | 提示词先是一份契约：格式与矛盾项决定可复算性 | C13 工程字段级（93.0） |
| E 实效派 | 价值只在能否换来真实可执行的动作 | C15 极深全量（90.5） |
| K 风险派 | 一次编造就毁掉全部产出，先保证不错 | C15 极深全量（89.8） |

- Borda 聚合：C13 = 43 > C15 = 40 > C05 = 37 > C16 = 36
- **多数投票：C15 获 2 票（E + K 双提名）→ 冠军**
- 链间序一致性 Kendall τ：S-E 0.65 / S-K 0.70 / E-K **0.917**（E 与 K 高度同向，S 才是真正的异见者）
- **并列处理**：首版按 id 拆并列，掩掉了 `C09 = C12`（Borda 同为 27）。门禁抓出来后改为「先比三链均分」的有实义次级判据 —— 27 分并列由均分拆开（C12 87.27 > C09 86.85），真歧义归零。按 id 拆并列等于没拆，因为 id 与质量无关。

> 诚实记录：Borda 首名与多数投票结果**不一致**（C13 vs C15）。这是真实分歧，不是四舍五入误差——S 链把 C15 压到第 6，因为它的 5000 字上限和「深推×五项自检」软冲突扣了分；而 E/K 认为这两点不足以抵消它的检索与自检强度。**按预设规则，多数投票优先**，但分歧同时成为终极版必须修 C15 弱点的理由。

## 五、三条候选真跑（同题、同输入、互不可见）

C05 / C13 / C15 各用同一份事实清单、同一任务、只读权限，跑真实仓库。

### 输出侧体检（4 维）

| 候选 | G1 事实可核验 | G2 格式自洽 | G3 自检落地 | G4 带路径动作 | 执行四维综合 |
| --- | --- | --- | --- | --- | --- |
| C05 | 100.0% | 33 | 20 | 11 | 70.60 |
| C13 | 100.0% | 17 | 20 | 9 | 67.40 |
| C15 | 96.7%（2 处无据） | 50 | 20 | 18 | 72.67 |

**静态排名与真跑排名在冠军上一致**（都是 C15），双通道互证。

### 真跑暴露的三条缺陷（静态评分发现不了，必须真跑才有）

1. **数字抄注释**：C15 里写「全站实有 11 个 scene」，C13 写 12，C05 写 11；实测 `ask()` 场景字面量 **10 个**。三份全错，全因直接引用代码注释。
2. **四类自检字面落地率 0/3**：三份都用自己的分类（事实/格式/边界/动作）替换了点名的四类，G3 齐刷刷 20 分。提示词里「自检强度」拉满也没用——**没有字面锁就等于没要求**。
3. **格式自洽只有 17–50 分**：无一家严守自己声明的格式，C13 仅命中 1/6 项。

### 真跑带来的实质发现（三条链独立收敛）

- **跨页 AI 衔接不是待办，是已交付**：`crossSceneHints()` 在 `utils/ai-agent.js:93`，`:124` 注入，TTL 10 分钟，`_test-cross-scene-ai.mjs` 实跑 10 通过 / 0 失败，已入 `allcheck.sh`。记忆里「差 400 字节主包预算所以没上」这条阻塞理由**已失效**。
- **`MAX_SCENES = 8` < 实测 10**，而门禁只断言 `>= 8`（`check-ai-fallback.mjs:92`）——阈值低于事实，等于把已知不足判绿。
- **冷启动真实失效点不是容量，是 `_sceneTs` 纯内存**（`utils/ai-agent.js:31`）：进程被回收后他页 `_sceneTs` 为 0 → `now - 0 > 10min` → 跨页提示恒不注入。
- **「613 家零坐标」全仓 0 命中**：这是我从旧记忆写进事实清单的，仓库里查无出处。三份真跑**都拒绝引用它**，并给出实测口径 `(0,0) 299 + 无坐标 371 = 670`。事实清单已按此更正。

## 六、终极提示词

冠军 C15 + 五个静态弱点的定向修复 + 三条真跑暴露缺陷的反向加固 = **8 条修复**，全部可被 `ultimate.mjs` 逐条断言。

| # | 来源 | 问题 | 终极版做法 |
| --- | --- | --- | --- |
| 1 | C15 C2=78 | 单一 5000 字上限守不住 | 分层配额：正文 ≤1200 / actions+risks ≤600 / selfcheck ≤200 + 明确删减顺序 |
| 2 | C15 C4=88 | 深推 + 五项自检写成过程日志 | 「思考过程不外倒」，自检独立占字段不计正文配额 |
| 3 | C15 C3=83 | 术语堆叠难读 | 保留术语但首现一句话解释 |
| 4 | C05 R2=30 | 会标不确定性但没有降级路径 | 两件事拆成两条独立条款 |
| 5 | C13 R2=62 | 同样只有一侧 | 同上，双侧补齐 |
| 6 | 真跑① | 数字抄注释 | 数量类数字必须自己数并附计数命令，注释数字只作线索 |
| 7 | 真跑② | 四类自检字面落地 0/3 | selfcheck 五条**逐字锁**「错别字：/逻辑漏洞：/代码bug：/数据准确性：/复跑：」 |
| 8 | 真跑③ | 格式自洽 17–50 分 | 8 字段名逐字出现、各占一行，不许改写不许合并 |

工程化技巧（用户要求的四项）落地位置：多步骤 CoT → §3 四阶段 P1–P4 各有具名产出物；关键节点自检 → §4 的 CP1/CP2/CP3；标准化输出格式 → §5 的 8 字段表；精准业务约束 → §8 的 8 条项目红线。

冲突消解：§7 写明 5 级优先级链（合规零伪造 > 事实准确 > 可执行性 > 格式 > 篇幅语气）+ 3 条已知矛盾的特例裁决。依据是 GPT-5 Prompting Guide「指令层级冲突一经消解，表现大幅提升」。

Qwen3 适配：`/think` / `no_think` 双开关、thinking 档 temp 0.6 / top_p 0.95 / top_k 20、**禁用 greedy decoding**、多轮历史只留最终输出（不回填思考内容）。

## 八、复跑方式

```bash
node tools/prompt/pool.mjs --md docs/prompt-engineering/candidates-v1211.md   # 重新生成候选池
node tools/prompt/rank.mjs --md docs/prompt-engineering/rank-v1211.md \
                           --json docs/prompt-engineering/rank-v1211.json     # 重新打分与聚合
node tools/prompt/ultimate.mjs                                                 # 终极版结构自检（12 段 / 8 字段 / 8 条修复）
node tools/prompt/verify-output.mjs <output.md> --json out.json                # 输出侧四维体检
node tools/check/check-prompt-lab.mjs                                          # 防回潮门禁
```

`check-prompt-lab.mjs` 已串进 `allcheck.sh` 既有「审计整改 + AI 全场景守卫」那一步，**步数仍为 61**。
它守的是：候选池自洽、四项偏置控制、评分幂等、落盘不漂移、真跑产出可核验率 ≥80%。
改了条款库或权重却忘记重新生成文档 —— 门禁判红，这是它最主要的价值。
