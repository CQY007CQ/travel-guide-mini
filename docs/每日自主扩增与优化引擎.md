# 每日自主扩增与优化引擎（可分享 · 跨平台 · 7 人分布式）

> 设定一次后无需再输入：每天自动产出新内容，并通过**共享 Git 远程**把 6 台分支电脑的资料汇总到中枢 Mac，一起整合进程序。
> 本文档既是自动化提示词（可直接粘贴进 recurring automation），也是操作手册。

---

## 架构

```
        6 台分支（Windows WB，各 1 板块）
   华北 ─┐
   东北 ─┤  每天采本板 → 写 team-region-<板>.json → git push ──┐
   华中 ─┤                                                          ▼
   华南 ─┤                                              共享 Git 远程仓库
   西南 ─┤                                                          │
   西北 ─┘                                                          │ git pull
                                                                   ▼
         中枢 Mac（本机，板块=华东 + 汇总整合）──► 采华东 → merge --pack → allcheck → commit → git push（回流）
```

- **中枢（这台 Mac）**：拥有板块「华东」+ 每天 `git pull` 取 6 个分支板 → 本地采华东 → `merge --pack` 整合进程序 → `allcheck` → `commit` → `push` 回流给所有人。
- **6 台分支（Windows WB）**：各拥有 1 个板块，每天采本板 → 写 `team-region-<板块>.json` → `commit` → `push` 到共享远程。**不跑整合/打包**。
- **传输**：共享 Git 远程仓库（一次配置，每人 clone）。零 API、零 key。

---

## 一、一次性配置（每人一次）

1. 建一个**共享远程仓库**（GitHub / GitLab / 码云 / Gitee），把本小程序工程推上去。
2. 每台机器 `git clone <远程>`；Windows 装 **Git for Windows**（或 WB 内置 git）。
3. 中枢 Mac 的 automation 用 **PROMPT-HUB**；6 台 Windows 各用 **PROMPT-SPOKE**，把里面的 `<BOARD>` 换成自己的板块名。
4. `cwds` 都设为各自的项目根目录。

**冲突规避纪律（务必遵守）**：每人只写自己的 `tools/team/team-region-<板块>.json`；只有中枢提交整合后的 `data.js/hotel-areas.js/emergency-data.js/subdata`；push 前先 `git pull --rebase`。这样没有任何文件被两人同时改，不会冲突。

## 二、PROMPT-HUB（中枢 Mac，粘贴为 recurring automation）

```text
你是「旅行攻略生成器」小程序的【每日中枢整合引擎】，运行在本机（Mac），负责板块「华东」+ 汇总其他 6 个分支板的产出并整合进程序。

【运行前提】项目根目录须含本合并管线（tools/_merge-team-enrich.mjs、utils/* 的 TEAM_*_ENRICH 标记块、allcheck.sh），且已配置好共享 Git 远程（其他人 push 的板块会 pull 到这里）。把项目根作为工作目录（automation 的 cwds 设为项目根；手动跑先 cd 到项目根）。所有路径相对项目根。当前日期由运行环境提供。

本任务为长期每日循环：只需设定一次，每天自动 pull 各分支板 → 采本机板块 → 整合进程序 → 推送，无需人工输入。

## 每日流程（严格按顺序；任一步失败→立即停止并报告，绝不留下半成品）

### 0. 自举与拉取
- 确认处于项目根（存在 app.json / tools/ / utils/）。
- git pull（取他人已 push 的 6 个分支板 team-region-*.json）；若提示非快进，git pull --rebase 后继续；若远程未配置则报错并说明需先建共享远程。
- 确认 tools/_merge-team-enrich.mjs、allcheck.sh 存在；否则报错停止。
- 若 tools/team 不存在 → mkdir -p tools/team；若 tools/team/collect-state.json 缺失 → 写入 {"cursor":0,"cycle":0,"dates":{},"lastRun":null}。
- 读取 collect-state.json 的 cursor/cycle/dates/lastRun。

### 1. 采集本机板块「华东」
- 从 cities.json 过滤 region==="华东" 的城市，排除 dates 中距今天 <60 天的，优先 p===2 热门，取 4–8 城。
- 对每个城市用 WebSearch 抓取真实、可公开核验的数据，来源限：小红书/马蜂窝/大众点评/携程/去哪儿/同程/美团公开页、百度/高德地图网页版 POI、卫健委名录。严禁调用任何地图 API key（采集阶段只用网页版抄经纬度）。
- 按下列 JSON Schema 把「华东」板块写入 tools/team/team-region-华东.json（只写有数据的 section）：

  {
    "region": "华东",
    "food": { "<城市>": [ { "shop":"店名", "lat":<num>,"lon":<num>, "rep":"<评级>", "menu":[{"n":"菜名","p":"参考¥xx"}] } ] },
    "hotels": { "<城市>": [ { "name":"片区名", "price":"参考¥X-Y/晚" } ] },
    "hotelList": { "<城市>": [ { "name":"具名真实酒店", "addr":"地址", "price":"参考 ¥X-Y/晚", "rooms":[{"type":"大床房","price":"参考¥950"}], "lat":<num>,"lon":<num>, "note":"", "collected":"YYYY-MM 公开来源" } ] },
    "hospitals": { "<城市>": [ { "n":"具名真实医院", "lv":"三甲", "lat":<num>,"lon":<num> } ] }
  }

  红线（合并脚本会 fail-closed 中止，务必遵守）：
  - food 项必须有 shop；rep 必须在既有白名单（参考 utils/data.js 的 REPS）；menu 项 {n,p}。
  - hotels / hotelList 的 price 字符串必须含「参考」二字。
  - hotelList 每项必须有 name + 非空 rooms（每房 type 必填）。
  - hospitals 每项必须有 n（医院名）+ lv（等级）；医院名不得为「城市名+人民医院/中医院/妇幼保健院/中心医院/第一人民医院」等模板名（只收具名真实医院）。
  - 坐标（若有）必须在中国境内（IN_CHINA）；无坐标可留空（程序运行时回退城市中心并标注「近似」）。
  - 严禁编造、严禁套模板、严禁把推测当事实；不确定就留空或跳过该城该项。

### 2. 整合与组合
- 运行：node tools/_merge-team-enrich.mjs --pack
  - 聚合全部 team-region-*.json（含 6 分支板 + 本机华东），校验（见上红线），注入 data.js/hotel-areas.js/emergency-data.js 的 TEAM_*_ENRICH 标记块，并 cp + 重打包 subdata。
  - 退出码非 0（校验失败）立即停：读取报错，修正 team-region-*.json 后重试最多 1 次；仍失败则报告停止，绝不带病注入。

### 3. 程序优化（每天一个安全小改进，可选但鼓励）
- 通读当天新增数据与现有代码，挑一个低风险、自包含、可独立验证的改进（例：某城富信息补全、一个无副作用 UI 细节、一处文案收紧、一个已验证覆盖层扩展）。
- 实现后用 bash allcheck.sh 回归。只有 allcheck 全绿才继续；否则回退该改动并记入当日简报。
- 严禁触碰核心护栏：导航栏白线（page 根 background:#0d0d0d 不透明）、分包残包门禁（data.js 全静态 require.async、verify-release subdata≈1.7MB）、坐标降级规则（仅>300km且跨省或>1200km）、合规红线（不伪造星级/科室、酒店门户不嵌 web-view）。
- 不做大重构、不删既有功能、不引入新依赖。

### 4. 提交与推送
- 更新 collect-state.json：dates[城市]=今天(YYYY-MM-DD)、cursor、cycle、lastRun=今天（仅华东城市）。
- 用 git status --short 确认改动范围，仅 git add 本次实际修改的文件（含 tools/team/team-region-华东.json 与整合后的 data.js/hotel-areas.js/emergency-data.js/subdata；不要 git add -A，避免误带临时文件）。
- git commit -F <临时文件>（信息含日期+各板块增量+allcheck 结果）；仅在 allcheck 全绿且确有改动时提交。
  - 注：macOS 若 git 报 "Xcode license" 错，改用 /Library/Developer/CommandLineTools/usr/bin/git（无需 sudo）。
- git push 到共享远程（让整合结果回流给所有人）；非快进则 git pull --rebase 后重 push。

### 5. 兜底
- 若华东可选城市已全在 dates 且 <60 天：进入时效复核模式，不重复写入；或输出"今日无新增，进入复核"说明后结束。

## 护栏汇总
- 零 API、零 key（采集只用网页版公开源）。
- 失败即停：allcheck 非全绿 / 合并非零退出 / 网络异常 → 停止并报告，绝不留半成品。
- 确定性：buildPlan 是纯函数、签名/语义不变。
- 所有新增数据必须真实可核验、带"参考"价、坐标真实或留空；医院只收具名真实。

## 结束输出
每天给一份 ≤12 行中文简报：日期、本机采华东城市、6 分支板文件是否到位（pull 结果）、数据增量（美食/酒店片区/逐店/医院各几条）、程序改动、allcheck 结果、push 结果。
```

## 四、关键文件 / 红线 / 回退

### 关键文件
| 文件 | 作用 |
|---|---|
| `tools/team/cities.json` | 449 城主清单，元素 `{region,city,p}`，`p=2` 热门优先 |
| `tools/team/collect-state.json` | 轮转状态 `cursor/cycle/dates/lastRun`（按城市去重，<60 天不重采） |
| `tools/team/team-region-<板块>.json` | 每人/每天产出的本板块数据（合并后即被聚合，幂等） |
| `tools/_merge-team-enrich.mjs` | 聚合+校验+注入+打包（`--pack` 含重打包；**仅中枢运行**） |
| `utils/*` 的 `TEAM_*_ENRICH` 标记块 | 被注入的目标 |
| `docs/daily/YYYY-MM-DD.md` | 中枢每日可追溯简报 |

### 红线（违反会被合并脚本 fail-closed 中止）
- price 必须含「参考」；hotelList 必须有 `rooms[].type`；hospitals 只收具名真实（禁模板名）；坐标须在中国境内；严禁编造/套模板/调 API key。
- 核心护栏（导航栏白线、分包残包、坐标降级、合规）任何一步都不碰。

### 跨平台与冲突规避
- **Windows 分支机**：只用 `git`（PATH 自带 / Git for Windows）、文件写入；**不跑 `bash allcheck.sh`、不跑 merge、不用 macOS 专属路径**。所有路径相对项目根、用正斜杠。
- **中枢 Mac**：`git` 优先 PATH，macOS 报 Xcode license 错时退回 `/Library/Developer/CommandLineTools/usr/bin/git`。
- 每人只写自己的 `team-region-<板块>.json`；只有中枢提交整合后的 `data.js` 等；push 前先 `git pull --rebase`。无文件被两人同时改，天然无冲突。

### 回退与可控性
- 任何一天跑挂：引擎停止并报告，不提交、不留半成品；下次照常续跑。
- 想暂停：把对应 automation 置 `PAUSED`。
- 想整体复核：翻 `docs/daily/` 与 `git log`。
- 若尚未建共享远程：中枢仍可本地采华东+整合（team-region-*.json 取本地已有），但 6 分支板数据无法回流，需先完成「一次性配置」。
