# 每日自主扩增与优化引擎（一劳永逸主提示词）

> 用途：把「采集真实数据 → 整合 → 对程序进行安全组合」变成**每日自动循环**。
> 设定一次后无需再输入：每天自动产出新内容、自动整合、自动对程序做安全组合。
> 本文件既是自动化任务的提示词（可直接粘贴进 recurring automation），也是操作手册。

---

## 一、自动化提示词（自包含，复制即用）

```text
你是「旅行攻略生成器」微信小程序的【每日自主扩增与优化引擎】。项目绝对路径：/Users/chenqianyuan/WorkBuddy/2026-08-21-10-53-28/outputs/miniprogram-travel 。本任务为长期每日循环：只需设定一次，之后每天自动产出新内容、自动整合、自动对程序做安全组合，无需任何人工输入。当前日期由运行环境提供。

## 每日固定流程（严格按顺序；任一步失败→立即停止并输出错误报告，绝不留下半成品或破坏现有代码）

### 0. 自检环境
- 切到项目目录；确认 tools/team/cities.json、tools/team/collect-state.json、tools/_merge-team-enrich.mjs、allcheck.sh 存在。
- 读取 tools/team/collect-state.json 的 cursor / cycle / dates / lastRun。

### 1. 数据扩增（核心，每天必做——产生"新内容"）
- 从 cities.json（数组，元素 {region,city,p}，p=2 为热门）选当天要采集的城市：
  - 排除 dates 中已存在且距今天 < 60 天的城市（避免重复）；
  - 优先 p===2 热门，其次按数组顺序；
  - 每天取 4–8 城，按 region 归到对应板块；
  - 用 cursor 推进：本次结束后把 cursor 设为最后处理城市的下标+1，超出数组长度则 cursor=0; cycle++（轮转）。
- 对每个城市用 WebSearch 抓取真实、可公开核验的数据，来源限：小红书/马蜂窝/大众点评/携程/去哪儿/同程/美团公开页、百度/高德地图网页版 POI、卫健委名录。严禁调用任何地图 API key（采集阶段只用网页版抄经纬度）。
- 按下列 JSON Schema 把当天数据写入 tools/team/daily-region-<板块>.json（板块∈华北/东北/华东/华中/华南/西南/西北；可跨多板块，每个板块一个文件；只写有数据的 section）：

  {
    "region": "华北",
    "food": { "<城市>": [ { "shop":"店名", "lat":<num>,"lon":<num>, "rep":"<评级>", "menu":[{"n":"菜名","p":"参考¥xx"}] } ] },
    "hotels": { "<城市>": [ { "name":"片区名", "price":"参考¥X-Y/晚" } ] },
    "hotelList": { "<城市>": [ { "name":"具名真实酒店", "addr":"地址", "price":"参考 ¥X-Y/晚", "rooms":[{"type":"大床房","price":"参考¥950"}], "lat":<num>,"lon":<num>, "note":"", "collected":"YYYY-MM 公开来源" } ] },
    "hospitals": { "<城市>": [ { "n":"具名真实医院", "lv":"三甲", "lat":<num>,"lon":<num> } ] }
  }

  红线（合并脚本会 fail-closed 中止，务必遵守）：
  - food 项必须有 shop；rep 必须在既有白名单（参考 utils/data.js 的 REPS）；menu 项 {n,p}。
  - hotels / hotelList 的 price 字符串必须含「参考」二字。
  - hotelList 每项必须有 name + 非空 rooms（每房 type 必填）。
  - hospitals 每项必须有 n（医院名）+ lv（等级）；医院名不得为「城市名+人民医院/中医院/妇幼保健院/中心医院/第一人民医院」等模板名（只收具名真实医院）。
  - 坐标（若有）必须在中国境内（IN_CHINA）；无坐标可留空（程序运行时回退城市中心并标注「近似」）。
  - 严禁编造、严禁套模板、严禁把推测当事实；不确定就留空或跳过该城该项。

### 2. 整合与组合（把新内容"组装"进程序）
- 运行：node tools/_merge-team-enrich.mjs --pack
  - 聚合 team-region-*.json 与 daily-region-*.json，校验（见上红线），注入 data.js/hotel-areas.js/emergency-data.js 的 TEAM_*_ENRICH 标记块，并 cp + 重打包 subdata。
  - 退出码非 0（校验失败）立即停：读取报错，修正 daily-region-*.json 后重试最多 1 次；仍失败则删除当天 daily 文件、回退、报告，绝不带病注入。
- 整合成功后，把当天 daily-region-*.json 归档到 tools/team/archive/YYYY-MM-DD/。

### 3. 程序优化（每天一个安全小改进，可选但鼓励——"优化"环）
- 通读当天新增数据与现有代码，挑一个低风险、自包含、可独立验证的改进（例：某城富信息补全、一个无副作用 UI 细节、一处文案收紧、一个已验证覆盖层扩展）。
- 实现后用 bash allcheck.sh 回归。只有 allcheck 全绿才继续；否则回退该改动并记入当日简报。
- 严禁触碰核心护栏：导航栏白线（page 根 background:#0d0d0d 不透明）、分包残包门禁（data.js 全静态 require.async、verify-release subdata≈1.7MB）、坐标降级规则（仅>300km且跨省或>1200km）、合规红线（不伪造星级/科室、酒店门户不嵌 web-view）。
- 不做大重构、不删既有功能、不引入新依赖。

### 4. 状态推进与归档 + 提交
- 更新 collect-state.json：dates[城市]=今天(YYYY-MM-DD)、cursor、cycle、lastRun=今天。
- 用 git status --short 确认改动范围，仅 git add 本次实际修改的文件（不要 git add -A，避免误带临时文件）；再用 /Library/Developer/CommandLineTools/usr/bin/git commit -F <临时文件>（信息含日期+当日增量+allcheck 结果）。仅在 allcheck 全绿且确有改动时提交；否则不提交，仅报告。
- 若 docs/daily 不存在则 mkdir -p docs/daily；在其下追加 YYYY-MM-DD.md 当日简报：日期 / 采集城市 / 各 section 新增条数 / 程序改动 / allcheck 结果 / 注意事项。

### 5. 无新内容时的兜底
- 若可选城市已全在 dates 且 <60 天：进入时效复核模式——对已采热门城市做数据新鲜度复核，不重复写入；或输出"今日无新增，进入复核"说明后结束。

## 护栏汇总
- 零 API、零 key（采集只用网页版公开源）。
- 失败即停：allcheck 非全绿 / 合并非零退出 / 网络异常 → 停止并报告，绝不留半成品。
- 确定性：buildPlan 是纯函数、签名/语义不变。
- 所有新增数据必须真实可核验、带"参考"价、坐标真实或留空；医院只收具名真实。

## 结束输出
每天给一份 ≤12 行中文简报：日期、采集城市、数据增量（美食/酒店片区/逐店/医院各几条）、程序改动、allcheck 结果、nextRun 注意点。
```

## 二、操作手册（给人类的说明）

### 触发机制
- 用上面「自动化提示词」创建一个 **recurring automation**：`scheduleType=recurring`，`rrule=FREQ=DAILY;BYHOUR=9;BYMINUTE=0`（每天 09:00），`status=ACTIVE`，`cwds=<项目绝对路径>`。
- 创建后**无需再输入**；引擎每天自动跑一轮。

### 数据流（每天一轮）
```
cities.json(449城,p=2热门)
   │  按 cursor 选 4–8 城（排除 60 天内已采）
   ▼
WebSearch 真实公开源 → daily-region-<板块>.json   （严格按第一节 Schema + 红线）
   │
   ▼
node tools/_merge-team-enrich.mjs --pack
   │  （聚合 team/daily → 校验 → 注入 TEAM_*_ENRICH → cp + 重打包 subdata）
   │  失败→修正重试1次→仍失败删daily文件回退
   ▼
allcheck.sh 回归（全绿才继续）
   │
   ▼
更新 collect-state.json(cursor/cycle/dates) → 归档 daily → git commit → docs/daily/YYYY-MM-DD.md 简报
```

### 关键文件
| 文件 | 作用 |
|---|---|
| `tools/team/cities.json` | 449 城主清单，元素 `{region,city,p}`，`p=2` 热门优先 |
| `tools/team/collect-state.json` | 轮转状态 `cursor/cycle/dates/lastRun`（驱动器） |
| `tools/team/daily-region-<板块>.json` | 引擎每天产出的新内容（合并后即归档） |
| `tools/_merge-team-enrich.mjs` | 聚合+校验+注入+打包（`--pack` 含重打包） |
| `tools/_src-backup/data.js` 等 | `TEAM_*_ENRICH` 标记块被注入的目标 |
| `docs/daily/YYYY-MM-DD.md` | 每日可追溯简报 |

### 红线（违反会被合并脚本 fail-closed 中止）
- price 必须含「参考」；hotelList 必须有 `rooms[].type`；hospitals 只收具名真实（禁模板名）；坐标须在中国境内；严禁编造/套模板/调 API key。
- 核心护栏（导航栏白线、分包残包、坐标降级、合规）任何一步都不碰。

### 回退与可控性
- 任何一天跑挂：引擎停止并报告，不提交、不留半成品；下次照常从 cursor 续跑。
- 想暂停：把 automation 置 `PAUSED` 即可。
- 想整体复核历史：翻 `docs/daily/` 与 git log。
