# 功能表 × 真实代码库对照 · 网页版

日期：2026-11-10　对象：`web/` + `tools/web/`（由小程序同一份源码编译到浏览器）
配套文档：`docs/功能对照-小程序版-2026-11-10.md`（图中 24 条的小程序端落点、库中额外 24 项能力）

---

## 结论先行

- 网页版**不重写业务逻辑**：`tools/web/build.mjs` 把小程序 `pages/`、`subpkg/`、`subai/`、`utils/` 的 JS 原样注册进模块表，WXML 由 `tools/web/wxml.mjs` 编译，WXSS 转 `rpx → calc`，`web/lib/runtime.js` 提供 `wx` 适配层。因此图中 22 项功能在网页端是**同源可用**，不是另做一套。
- 本轮之前网页端有 **6 处会让功能「看着在、点了没反应」的降级缺陷**，已全部修复并加防回潮断言：数据分片只加载第 1 块、`getApp()` 没有 `setPlan`、query 被吞、下拉/日期选择器不可用、GET 请求参数丢失、地图标点事件丢失。
- 用户要求的「**内置 AI 真正服务整个网页**」已落地：助手从孤立悬浮窗升级为全站智能体，能读当前页面与本机状态、能直接生成并写入行程、能带参数跳到任意一页。
- 「网页更多跳转功能」已落地：与 `app.json` 同源的 **17 页全站导航抽屉**、非 tab 页顶部返回栏、`?query` 深链、键盘快捷键。
- 验证：`node tools/web/smoke.mjs` **56 项全绿**（含真实执行 AI 生成行程、带参跳转、站点状态问答）。

## 2. 本轮网页端实际修复（问题 → 根因 → 修法 → 验证）

| # | 问题 | 根因 | 修法 | 验证 |
|---|---|---|---|---|
| 1 | 数据缺一整块 | `tools/web/build.mjs` 只注册 `data-packed.js`，且把 `_manifest.js` 排除出模块表 → `utils/data.js` 在浏览器里 fallback 到单块 | 由 `_manifest.js` 清单驱动注册**全部**数据块（将来切第 3 块自动跟上），manifest 保留在 `modules.js` | `smoke.mjs` 断言清单每块已注册，且 `SPOT_CARDS_BY_CITY` / `SPOT_DETAILS_BY_CITY` 真实进入运行时 |
| 2 | 首页「生成攻略」点了报错 | `__bootWeb` 只给 `getApp()` 挂了 `globalData`，各页 `app.setPlan()` 拿到 undefined | `APP = Object.assign({}, appConfig, {globalData})`，保留同一 globalData 引用 | 静态护栏 + AI 动态生成行程写入 `globalData` |
| 3 | 带参跳转永远失效 | `cleanUrl()` 用 `split("?")[0]` 吞掉 query，`__mountPage` 的 `onLoad` 恒传 `query:{}` | cleanUrl 保留 query；`router` 解析并透传；`__mountPage(path, query)` 传给 `onLoad`；`redirectTo/reLaunch` 走 `replaceState` | 「看第 2 天地图」实测 `di=1`（map.js 为 0-based） |
| 4 | 所有下拉选择点不动 | `<picker mode="selector">` 编译成 0 个 option 的空 `<select>`，CSS 还 `display:none` 遮丑 | `wxml.mjs` 把 `range` 表达式传给 `__pick`，运行时生成 option（value = 索引，对齐小程序 `e.detail.value`），CSS 改为可见 | 静态护栏：生成 option + 回填 `selectedIndex` |
| 5 | 日期选择初值错误、改了不触发 | 初值传的是 `"{{depart}}"` 字面量；`__ev` 挂在被隐藏的 select 上，用户操作的是新建 input | 初值/start/end 用真实表达式编译；`__ev` 与 `dataset` 复制到真正可操作的 input | 静态护栏：事件复制 |
| 6 | 天气/地理 GET 丢参数 | `fetch` 不会像小程序那样自动把 `data` 拼到 query | GET 自动拼 query，非 GET 统一处理 body，返回真实 `statusCode` | 静态护栏 |
| 7 | 分享长图导出取不到画布 | `createSelectorQuery().fields({node:true})` 只回 rect，不回 DOM 节点 | `fields` 返回 `node` / rect / size / dataset | 静态护栏 |
| 8 | 地图标点点了没反应 | `EVT_MAP` 缺 `markertap` / `callouttap`，SVG 示意图没有事件委托 | 补事件映射；`__schematic` 给圆点加 `data-mid`；`__h` 点击委托还原原始 `markerId` 并调页面 handler | 静态护栏 |
| 9 | 拖拽中断不收尾 | `touchcancel` 在编译器有映射，运行时没监听 | `bindEvents` 补 `touchcancel` / `reset` | WXML 编译器断言 |
| 10 | 只能在 4 个 tab 之间走 | 网页外壳没有全站页面入口 | 构建生成 `web/lib/nav.js`（17 页，来自 `app.json` + 各页 `.json` 标题）；抽屉 + 顶部返回栏 + `Alt+N/H/←` 快捷键 | `smoke.mjs` 校验清单与模板一一对应、4 个 tab 标记正确 |
| 11 | 页面变化时助手不知道 | 无页面变化通知 | `app.js onHash()` 派发 `web:pagechange`，AI 监听并刷新上下文与快捷提问 | AI 动态验证 |

**刻意未改**：`web/index.html` 的 CSP 出站白名单（`connect-src 'self' https://*.qweatherapi.com https://*.amap.com`）保持不动。放宽它会扩大 XSS 出站面，且可选大模型本就被设计为「被拦则优雅回退离线助手」，不属于功能缺陷。

## 3. 内置 AI：从悬浮窗升级为全站智能体

文件：`web/ai-assistant.js`（默认纯离线、零 Key）；页面清单来自 `web/lib/nav.js`。

### 3.1 能力矩阵

| 维度 | 之前 | 现在 |
|---|---|---|
| 感知范围 | 只读离线城市/美食/地标库 | 当前页 `path` + `query` + 页面实例 `data` + `globalData.plan` + 账本 + 行李清单 + 足迹 + 准备项 |
| 跳转能力 | 只能跳 `pages/plan/plan` 与 `pages/more/more` | 全站 17 页（清单与 `app.json` 同源），支持带 `?query`；地图可指定 `di=第 N 天` |
| 干活能力 | 只回一句「去规划页」 | 调 `T.findCity()` + `T.buildPlan()` + `app.setPlan()` **真正生成并写入行程**，再自动切到行程页 |
| 站点问答 | 无 | 今日花费、总花费/预算对比、行程体检、出发倒计时、今日剩余安排与动线步行量、行李清单进度、足迹、最累的一天 |
| 检索结果 | 只给文字 | 每条回答附「直达对应页」动作按钮（美食页 / 按标签找景点 / 深度玩法 / 账本 / 出行准备 / 地图 …） |
| 快捷提问 | 固定 6 条 | 按当前页切换（15 组页面专属 chip），监听 `web:pagechange` |
| 对外接口 | 无 | `window.__webAI`：`ask` / `reply` / `go` / `context` / `generatePlan` / `open` / `close` |
| 大模型 | 可选，system prompt 无上下文 | 可选，system prompt 注入当前页面与行程摘要；默认纯离线，CSP 拦截时优雅回退 |

### 3.2 可直接使用的示例指令

| 说这句 | AI 会做 |
|---|---|
| `帮我生成成都3天行程` | 生成 3 天逐日行程 → 写入 `globalData.plan` → 自动切到「每日行程」页 |
| `看第2天地图` | 跳「地图导引」并带 `di=1`，直接展示第 2 天图层 |
| `打开美食页` / `去使用指南` | 一步切到对应页面 |
| `行程体检` | 调 `T.tripCheck()` 列出真实问题与建议 |
| `今天花了多少` / `总花费和预算对比` | 读本机账本，给出金额与预算进度 |
| `今天还剩几项安排` | 读 `T.todayState()` / `T.nextActivity()` / `T.dayMove()`，给剩余项、当前点、动线与步行量 |
| `还差几项没准备` | 读 `T.packSmart()` / `T.getPrepChecks()`，给清单进度 |
| `哪天最累` | 逐日调 `T.dayMove()` 算真实坐标里程，指出最长的那天 |
| `成都吃什么` | 列 `FOOD_SPOTS` 里的真实店铺与招牌，附「打开美食清单」按钮 |

### 3.3 零伪造约束

所有问答数据来自同源离线库与项目既有真实 API：**不编造店名、景点、医院、价格、星级、评分**。城市未收录时明确说「未收录具体店铺」，并给可执行的下一步（生成行程 / 打开对应页），不用通用话术填充。可选 LLM 的 system prompt 也写明「只能引用应用内已有数据，不确定就说未收录」。

## 5. 网页端仍有的结构性边界（浏览器 / 主体限制，非本轮 bug）

| # | 边界 | 代码依据 |
|---|---|---|
| 1 | 没有原生 `<map>` 组件，地图是真实坐标 SVG 示意图而非在线底图 | `web/lib/runtime.js` `__schematic()` / `webMapContext()` |
| 2 | 订阅消息与云开发推送不可用 | `runtime.js` `requestSubscribeMessage` 显式 fail + toast、`cloud: null` |
| 3 | 没有微信登录态与转发深链载体（分享卡、好友复现行程） | `runtime.js` `getAccountInfoSync()` 返回 `appId:"web"` |
| 4 | CSP 出站白名单只允许同源 + 和风 + 高德，不能直连任意第三方 API | `web/index.html` `Content-Security-Policy` |
| 5 | 可选大模型需用户自填 `baseURL` / `apiKey` / `model`，且禁止本机/内网地址 | `ai-assistant.js` `safeBaseURL()` / 设置面板 |
| 6 | 不能写系统日历，改为下载标准 `.ics` 文件 | `runtime.js` `addPhoneCalendar()` → `downloadICS()` |
| 7 | 无系统分享面板与相册保存，图片改为浏览器下载；拨号/地图为 `tel:` 与高德 URI 跳转 | `runtime.js` `saveImageToPhotosAlbum()` / `showShareImageMenu()` / `openLocation()` |
| 8 | 无微信分包按需加载、无激励视频广告（深度玩法 fail-open 全解锁） | `tools/web/build.mjs` 注释、`subai/utils/ad.js` |

**部署提醒**：构建产物 `web/lib/modules.js` 是 ignored/untracked 文件，包含本地内置凭据，因此网页版**只能本机预览，不能公网部署**。要公开须先完成凭据合规化（见小程序版文档第 4 节）。

## 7. 为什么两端共同发展

产品优先级仍是**小程序为主**；但个人主体未认证使 web-view、支付、云同步、订阅消息等能力无法解锁，上传体验版也卡在本人扫码登录。网页版作为**同源预览与交互试验场**，本轮先把「全站 AI、全站导航、深链跳转、数据完整加载」跑通并加了回归护栏；这些能力不依赖微信认证，可立即演示与验收。待主体升级后，可把新的交互形态按同源原则回流小程序端，而不是在两套代码里各写一遍。
